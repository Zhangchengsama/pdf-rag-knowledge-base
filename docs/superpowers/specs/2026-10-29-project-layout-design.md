# 项目目录整理

用户已在当前聊天批准按两步实施，保留业务逻辑、旧版本、上传文件和聊天记录。

1. 将当前 v6 的 Python 文件平铺移到 src；测试及评测题集移到 tests；说明文档移到 docs；v1 至 v5（含 v3 weight_rrf）原样移到 legacy。根目录 run.py 提供统一启动。项目根目录定位不依赖工作目录。
2. 上传原件使用 data/uploads，缓存使用 data/cache，聊天使用 data/conversations，共用设置使用 data/settings。通过末尾可选 output_path 参数支持集中缓存，省略该参数的旧业务调用继续使用 PDF 旁边的缓存。

现有上传的内容摘要目录及文件名保留。迁移脚本只逐个移动已核对的文件，不删除文件或目录；发生目标冲突时停止，不覆盖。保存迁移前文件清单及 SHA256 校验，用于核对资料完整性。旧请求保留原资料语义；通过路径映射解析迁移过的上传文件和缓存，不修改聊天正文。

保持 PDF 页序、切块、编码、HNSW、BM25、RRF、提示词、答案/来源结构、标题与重试行为不变。保留旧业务函数入口及默认参数行为。外部教材原件留在原位置；已有外部缓存可只读复制到集中目录，原文件保留。

验收：原有离线测试、根目录/异地工作目录启动、真实网页两个页面、上传/范围保存/建库复用/重试/旧聊天、迁移幂等与内容校验。测试不下载模型、不调用外部 API。
