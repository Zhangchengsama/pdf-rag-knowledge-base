## 已核实的问题

### 1. 首次建库传错 BM25 入参（高优先级）

- 位置：`rag_service.py:45`；`eval.py:148` 也有相同调用。
- 条件：PDF 同名 JSON 不存在，进入完整建库分支。
- 原因：`build_bm25` 需要已分词的二维语料列表，实际传入了 JSON 的 `Path` 对象。已有 JSON 的补建分支会先调用 `build_corpus`，两条路径处理不一致。
- 验证：执行实际 `building_data` 函数，隔离文件写入与模型编码，保留真实 `build_bm25` / `BM25Okapi`，复现 `TypeError: 'WindowsPath' object is not iterable`。
- 影响：首次问答在建库阶段中断，无法生成 BM25 缓存。

### 2. 评估函数依赖外部全局 k（高优先级）

- 位置：`eval.py:89`。
- 条件：导入后调用 `evaluate_model`，或全局 `k` 与参数 `final_k` 不一致。
- 原因：Hit@k 使用 `pages[:k]`，但函数的参数是 `final_k`；`k` 只在脚本入口赋值。
- 验证：用固定检索结果调用实际函数，导入场景复现 `NameError: name 'k' is not defined`。设置全局 `k=1`、`final_k=2`、正确页位于第二项时，命中被记为 0，期望为 1。
- 影响：作为函数调用会报错；参数不一致时指标失真。

### 3. 短文档无法满足固定候选数量（中优先级）

- 位置：`dense.py:123`；`rag_service.py` 的调用固定 `candidate_k=20`。
- 条件：知识库文本块少于 20 个，或调用方要求的 k 超过索引元素数。
- 原因：`knn_query` 前没有按实际元素数限制 k。
- 验证：使用本机真实 hnswlib 构建 2 条向量的内存索引并查询 `k=20`，复现 `RuntimeError: Cannot return the results in a contiguous 2D array. Probably ef or M is too small`。
- 影响：小型 PDF 的问答在稠密检索阶段失败；报错信息容易被误解为 ef 或 M 设置问题。

### 4. 评测集路径指向不存在的旧目录（中优先级）

- 位置：`eval.py:110`。
- 原因：入口仍引用 `v3 copy/eval_questions.json`，而本版本文件位于 `v6/test/eval_questions.json`。
- 验证：只读检查确认旧路径不存在，本版本评测集存在。
- 影响：即使模型与索引准备完成，运行入口仍会在加载问题集时报 `FileNotFoundError`。

### 5. 分词过滤仍保留空字符串（低优先级）

- 位置：`sparse.py:19` 起的过滤逻辑。
- 条件：分词结果包含空格、换行等纯空白项。
- 原因：`strip()` 先将其变成 `""`，后续条件却仅排除 `" "`、`"\n"` 与部分标点，没有排除 `""`。
- 验证：执行实际 `segment_text`，让分词器返回纯空白项，结果为 `['']`。
- 影响：空词进入 BM25 语料及查询，污染词频、文档长度和匹配分数。

## 已观察到的限制及边界风险

这些项目尚未确认是否违反当前预期，未作为已复现的日常功能故障处理。

- **PDF 只读取前 11 页**：`get_pdf.py:48` 在零基页下标达到 10 后退出。用 15 页的模拟文档执行实际提取函数，确实只返回前 11 页。这可能是测试时保留的限制；后续页不会进入知识库。
- **切块参数没有校验**：`split_text` 的步长是 `chunk_size - overlap`；非空文本遇到步长小于等于 0 时循环无法结束。默认参数正常；本次仅静态确认，没有运行会无限循环的输入。
- **缓存只检查存在性**：PDF 内容、嵌入模型或切块方式改变后，已有 JSON、NPY、PKL、BIN 不会自动同步更新。多个 PDF 共用同一个 `index_path` 还可能出现向量标签与原文错配。这是按代码分支推导的风险，未改动实际缓存复现。
- **空文本库无专门处理**：扫描版 PDF 没有文本层时可能产生空列表；此时向量数组没有第二维，`embeddings.shape[1]` 无法使用。当前提取流程没有 OCR。
